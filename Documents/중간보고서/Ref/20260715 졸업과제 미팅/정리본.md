## 0. 프로젝트 소개

### 목표

- 실내 공간을 3차원으로 재구성하고, 공간 구조를 반영해 계산한 와이파이 신호 분포를 시각화

```text
[그래픽스]

```

## 1.3 실내 공간 촬영 및 3차원 장면 재구성

### 사진 촬영

- 강의실을 여러 위치와 방향에서 촬영
- 총 205장의 사진 사용
- 같은 벽과 물체가 여러 사진에 반복해서 나타나도록 다양한 위치와 방향에서 촬영
- 사진 사이의 공통 특징점을 이용해 각 사진을 찍은 카메라의 위치와 방향 추정

### 3D Gaussian Splatting

- **3차원 가우시안 표현(3D Gaussian Splatting, 3DGS)**
  - 공간을 삼각형 표면만으로 표현하지 않음
  - 위치·크기·방향·색상·투명도를 가진 많은 가우시안으로 장면을 표현

- 각 가우시안은 공간의 작은 영역을 나타냄
- 카메라 시점에서 가우시안들을 화면에 투영하고 겹쳐 최종 색상을 계산
- 새로운 시점에서도 실제 사진과 유사한 장면을 빠르게 렌더링할 수 있음
- 본 프로젝트에서는 최종 실시간 화면을 만드는 **시각화용 장면 표현**으로 사용

### PGSR을 이용한 장면 재구성

- **사용 기법:** 평면 기반 가우시안 표면 재구성(PGSR: Planar-based Gaussian Splatting for Efficient and High-Fidelity Surface Reconstruction)
- **PGSR의 특징**
  - 일반적인 3DGS에 표면과 평면에 대한 제약 추가
  - 장면의 시각적 재현과 공간의 표면 구조 추출을 함께 수행

#### 가우시안이 표면을 형성하는 과정

1. 초기에는 가우시안들이 공간에 퍼진 흐릿한 점 구름과 비슷한 상태로 배치됨
2. 학습 과정에서 사진을 다시 렌더링한 결과와 실제 사진의 차이가 줄어들도록 가우시안의 위치·크기·방향·색상을 조정
3. PGSR의 평면·깊이 제약을 통해 가우시안이 벽과 물체의 표면 방향에 맞춰 점차 정렬
4. 가우시안들이 물체 표면을 따라 얇은 층처럼 밀집하면서 장면의 외형을 표현

#### Mesh 변환(표면 모델 추출)

- PGSR은 학습된 가우시안 분포를 기반으로 표면을 추정하여 Mesh로 변환하는 기능도 제공
- 일반적으로 TSDF(Truncated Signed Distance Function) 기반 융합이나 Poisson Surface Reconstruction과 같은 방법을 사용하여 가우시안으로부터 연속적인 표면을 복원
- 변환 결과는 OBJ, PLY로 출력
- 이 Mesh는 바로 전파 계산이나 추가적인 기하 분석에 활용할 수 있지만, 일부 영역에서는 구멍이나 노이즈가 포함될 수 있어 본 프로젝트의 파이프라인에서는 이후 후처리를 거침

![PGSR 가우시안 스플래팅 결과를 PLY Mesh로 변환한 강의실 장면](<Graphics/PGSR 결과 - Mesh.png>)

*그림 G-1. PGSR로 학습한 가우시안 스플래팅 결과를 PLY 형식의 삼각형 표면 모델로 변환한 결과*

### 3DGS와 Mesh를 함께 사용하는 이유

| 표현 | 장점 | 본 프로젝트의 역할 |
|---|---|---|
| 3D Gaussian Splatting | 사진과 유사한 장면을 빠르게 렌더링 | 사용자에게 보여줄 실시간 화면 |
| Triangle Mesh | 벽·바닥과 같은 명시적인 표면과 교차 판정 가능 | 전파 경로 계산과 히트맵 가림 판정 |

- **가우시안 장면의 특성**
  - 시각적으로 자연스러운 장면 생성에 적합
  - 전파가 어느 표면에 부딪혔는지 명확히 계산하기 어려움
- **Mesh의 특성**
  - 전파와 표면의 교차 계산에 적합
  - 원본 사진과 같은 사실적인 화면 생성에는 한계
- **역할 분리:** 화면은 3DGS, 물리 계산은 Mesh

### 결과

- 실제 강의실과 유사한 3차원 장면 생성
- 3DGS 기반 실시간 시각화용 장면 확보
- OBJ·PLY 형식의 표면 모델 확보
- 시각화와 전파 계산을 같은 공간 좌표에서 연결할 수 있는 기반 마련

## 1.4 전파 계산용 공간 모델 생성

- **PGSR Mesh의 상태**
  - 실제 강의실의 형태는 포함
  - 전파 계산에 그대로 사용하기에는 다음 문제가 존재
    - 촬영되지 않았거나 특징이 부족한 영역에 구멍 발생 가능
    - 벽과 바닥의 표면이 울퉁불퉁하거나 여러 조각으로 분리될 수 있음
    - 작은 노이즈와 불필요하게 많은 삼각형이 포함될 수 있음
    - 벽·바닥·천장의 경계가 정확히 맞지 않아 전파가 틈으로 빠져나갈 수 있음
    - 실제 길이 단위가 아니라 장면 내부의 상대적인 크기로 표현
- **전파 계산에 미치는 영향**
  - 시각적으로 잘 드러나지 않는 작은 구멍이나 표면 흔들림도 잘못된 통과·반사·차단을 생성할 수 있음
- **대응 방법**
  - 원본 Mesh를 그대로 수정하지 않음
  - 전파 계산에 중요한 구조만 사용해 별도의 단순하고 닫힌 공간 모델 생성

### 생성 과정

1. **평면 후보 검출:** 원본 표면 모델에서 바닥·천장·벽과 같이 넓은 평면 구조를 찾음
2. **사람의 선택과 확인:** 자동 검출 결과 중 실제 방을 구성하는 평면을 선택
3. **교차점 계산:** 선택한 평면들을 서로 교차시켜 방의 모서리와 경계 계산
4. **닫힌 방 생성:** 바닥·벽·천장이 같은 꼭짓점을 공유하도록 연결해 틈이 없는 구조 생성

![강의실 점군과 닫힌 공간 모델의 정합 결과](<Graphics/G-2 닫힌 공간 모델.png>)

## 1.5 전파 경로 및 신호 분포 계산

### 사용 도구: NVIDIA Sionna RT

- **Sionna RT**
  - NVIDIA에서 제공하는 전파 시뮬레이션 도구
  - 광선 추적(Ray Tracing)을 이용해 공간 안에서 전파가 이동하는 경로 계산
  - 내부적으로 Mitsuba 3 기반 장면과 광선 교차 계산 활용

### Sionna RT가 시뮬레이션 가능한 것들
- 벽·바닥·천장에 의한 반사와 감쇠
- 책상·칠판과 같은 장애물에 의한 직접 경로 차단
- 콘크리트·목재·금속 등 재질 차이에 따른 전파 반응
- 직접 경로와 여러 반사 경로가 함께 수신 위치에 도달하는 현상

#### 계산 방식

1. 전파 송신기의 위치·주파수·출력 조건 설정
2. 수신 위치 설정
3. 송신기에서 출발한 전파가 Mesh와 만나는 지점 계산
4. 수신기로 직접 도달하는 경로와 벽·바닥·장애물에서 반사되는 경로를 나누어 추적
5. 각 경로의 거리와 재질 특성에 따른 감쇠 계산
6. 여러 경로의 영향을 종합해 위치별 신호 세기 또는 경로 이득 계산

### 단순 거리 기반 계산과의 차이

- **단순 거리 모델**
  - 송신기에서 멀어질수록 신호가 약해진다고 가정
  - 벽·장애물·반사 경로에 따른 차이를 충분히 반영하기 어려움
- **실제 실내 공간**
  - 송신기와 같은 거리라도 벽의 유무에 따라 신호가 달라짐
  - 금속 장애물과 반사 경로의 존재 여부에 따라 신호가 달라짐

#### 가상 벽을 이용한 전파 차단·반사 테스트

- 가상 벽을 추가했을 때 직접 경로·반사 경로·신호 분포가 실제 계산 결과에서 달라지는지 확인
- **Baseline:** 장애물이 없는 기본 방
- **Variant:** 송신기와 수신기 사이에 가상 벽을 추가했을 때의 최종 결과

# 2. 네트워크·백엔드 파트

## 2.1 그래픽스 파트와의 연결 역할

- **핵심 역할**
  - 여러 장치에서 측정한 RSSI 수집
  - 측정값의 시간과 위치 정리
  - 여러 노드의 값을 하나의 프레임으로 구성
  - 구성한 프레임을 그래픽스 파트에 전달
- **그래픽스 파트에서 안정적으로 받아야 하는 정보**

| 그래픽스에 전달하는 정보 | 시각화에서의 용도 |
|---|---|
| RSSI | 해당 위치의 실제 신호 세기 입력 |
| 측정 위치 `(x, y, z)` | 3차원 장면 안에 측정값 배치 |
| 측정 시각과 서버 수신 시각 | 여러 노드의 값 동기화 및 지연 확인 |
| 노드 ID와 순번 | 데이터 출처 구분 및 누락 확인 |
| 회전 정보 | 향후 이동 장치의 시점과 방향 반영 |

- **현재 상태**
  - 수집 → 시간 동기화 → 저장 → 그래픽스 전달의 기본 경로 구현
  - 그래픽스 파트와 1차 연동 확인

---

## 2.2 전체 데이터 흐름

```text
여러 임베디드 노드의 RSSI 측정값
        ↓
서버에서 형식과 범위 검사
        ↓
가까운 시각의 측정값을 200ms 단위로 묶음
        ↓
위치·시간이 포함된 하나의 측정 프레임 생성
        ├─ 데이터베이스 저장
        ├─ 상태·지연 모니터링
        └─ WebSocket으로 그래픽스에 실시간 전달
```

- **200ms 단위 동기화의 목적**
  - 서로 다른 노드의 측정값이 약간씩 다른 시각에 도착하는 문제 처리
  - 가까운 시각의 값을 하나의 프레임으로 구성
  - 그래픽스에서 한 시점의 공간 표본처럼 사용할 수 있도록 변환

---

## 2.3 그래픽스 연동 과정에서 해결한 문제

### WebSocket 접속 방식 정리

- **초기 문제:** 실시간 데이터 주소를 브라우저 주소창에서 열어 접속 오류 발생
- **원인:** WebSocket은 일반 웹페이지가 아니라 프로그램 내부에서 연결하는 통신 방식
- **해결:** 그래픽스 프로그램의 WebSocket 클라이언트가 서버에 직접 연결하도록 구성

![WebSocket 주소를 브라우저에서 열었을 때의 접속 오류](<Graphics/N-1 WebSocket 접속 오류.jpg>)

*그림 N-1. 실시간 데이터 주소를 일반 웹페이지처럼 열어 발생한 접속 오류*

### 위치·방향 정보 추가

- **초기 메시지:** RSSI 중심으로 구성
- **추가 요구사항:** 그래픽스 장면 안에 측정값을 배치하기 위한 측정 시점 위치 필요
- **변경 내용**
  - 위치 `(x, y, z)`와 회전 정보를 메시지에 추가
  - 위치와 회전 정보를 데이터베이스에도 저장
  - 서버에서 임베디드 데이터를 그래픽스가 바로 사용하기 쉬운 구조로 변환
- **그래픽스 전달 형식 예시**

```json
"node-01": {
  "rssi": -58,
  "server_receive_ms": 1751000000560,
  "pos": {"x": 1.2, "y": 0.0, "z": 2.4},
  "rot": {"w": 1, "x": 0, "y": 0, "z": 0}
}
```

### 실제 네트워크 환경 문제

- 개발용 메시지 중계 프로그램에서 원격 장치의 데이터 전달 문제가 발생하여 표준 브로커인 Mosquitto로 교체
- 학교 공용 와이파이의 기기 간 통신 제한 때문에 별도 공유기 기반의 같은 내부망으로 구성
- 교체 후 원격 장치가 보낸 데이터가 서버·데이터베이스·모니터링 화면까지 도달하는 것을 확인

# 3. 임베디드 파트

## 3.1 그래픽스 파트에 제공하는 입력

- **핵심 역할**
  - 실제 공간에서 신호 세기 측정
  - 측정값을 그래픽스 시각화에 사용할 현실 데이터로 변환

- **계산값과 실측값 비교를 통해 가능한 작업**
  - 시뮬레이션 결과가 실제 측정 경향과 맞는지 확인
  - 계산 결과와 실측값의 차이 분석 필요할 경우 실측값을 이용해 히트맵 보정

- **현재 상태**
  - RSSI 측정부터 서버 전송까지의 기본 동작 구현 완료

---

## 3.2 전체 측정 흐름

```text
여러 위치의 ESP32가 와이파이 신호 세기 측정
        ↓
게이트웨이 ESP32가 여러 노드의 값을 한곳에 수집
        ↓
STM32가 손상된 메시지를 제외하고 노드별 최신값 정리
        ↓
노드 ID와 설치 위치를 결합해 서버로 전송
        ↓
그래픽스에서 실제 RSSI 표본으로 사용
```

- **현재 전송 구조**
  - 여러 센서가 각각 서버에 직접 접속하지 않음
  - 게이트웨이와 STM32에서 측정값을 한 번 정리한 뒤 서버로 전달
- **구조의 목적**
  - 센서 수가 늘어나도 서버가 동일한 형식의 데이터를 수신
  - 센서별 통신 차이를 서버 앞단에서 정리

---

## 3.3 현재 구현한 범위

| 구성 요소 | 현재 역할 | 상태 |
|---|---|---|
| ESP32 측정 노드 | 대상 AP의 RSSI 측정 및 간단한 평균 처리 | 구현 완료, 다중 실물 시험 필요 |
| ESP32 게이트웨이 | 여러 노드의 측정값 수집 및 누락 관리 | 구현 완료 |
| STM32 | 메시지 오류 검사, 노드별 최신값 관리, 서버용 데이터 생성 | 구현 및 기본 시험 완료 |
| 전송 브리지 | 노드 ID·설치 좌표 결합 후 MQTT 전송 | 서버 연결 확인 |
| 대시보드 연동 | 측정한 값을 서버로 보내 대시보드에 출력 | 진행 중 |

### 측정값 안정화

- RSSI는 같은 위치에서도 사람과 장애물, 간섭에 따라 흔들릴 수 있음
- 현재는 최근 5개 측정값의 이동평균을 사용해 순간적인 변동을 줄임

### 위치 정보 분리

- **노드 위치 관리 방식**
  - 노드 위치를 펌웨어에 고정하지 않음
  - 별도 설정 파일에서 노드 ID와 위치 좌표 결합
- **장점**
  - 센서를 다른 위치로 옮겨도 펌웨어를 다시 만들 필요 없음
  - 설정 파일의 좌표만 수정하여 배치 변경 가능
