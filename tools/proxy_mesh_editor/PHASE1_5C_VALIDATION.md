# Phase 1.5-C 실제 크기 보정 검증 결과

## 결론

기존 Room Envelope를 수정하지 않고 동일한 위상 구조의 미터 단위 사본을 생성했다. 바닥점 `0`은 원점, 장면 위쪽은 `+Z`, 바닥 모서리 `2→3`의 수평 투영은 `+X`로 정렬됐다. 회전 행렬식은 `+1`이며 면적·부피·평면·왕복 변환 검증을 모두 통과했다.

현재 배율은 사진에서 추정한 문 크기를 사용하므로 결과 상태는 `provisional`, 신뢰도는 `low`다.

## 기준 상태와 실행

- 기준 커밋: 로컬 `main`의 `2a1631fcae599b01a3af65ab6f8567644c648362`
- 원격 `main`: HTTPS 인증 정보를 사용할 수 없어 확인하지 못함
- 입력: `outputs/proxy_mesh/pnu_classroom/room_envelope/room_envelope.json`, `.obj`
- 입력 형상: 꼭짓점 8개, 삼각형 12개, 경계 모서리 0개
- 도구 버전: `0.5.0`

```bash
conda run -n pgsr python -m tools.proxy_mesh_editor.main calibrate-metric \
  --envelope-json outputs/proxy_mesh/pnu_classroom/room_envelope/room_envelope.json \
  --envelope-obj outputs/proxy_mesh/pnu_classroom/room_envelope/room_envelope.obj \
  --config tools/proxy_mesh_editor/configs/pnu_classroom_metric_calibration.yaml \
  --output outputs/proxy_mesh/pnu_classroom/metric_calibration
```

## 시각 확인과 한계

생성한 투시도와 위쪽 도표에서 다음을 확인했다.

- 바닥점 `0`이 원점이다.
- 천장점은 모두 `+Z` 방향에 있다.
- 바닥 모서리 `2→3`의 수평 투영은 `+X`다.
- 바닥점 Z가 `0.000~0.510 m`로 달라 원래 경사가 유지된다.
- 객체·그룹·면 선언 비교 결과가 입력과 동일하다.

현재 환경에는 MeshLab 실행 파일이 없어 MeshLab 자체의 여러 시점 렌더링은 확인하지 못했다. `room_envelope_metric.obj`와 `metric_coordinate_axes.ply`를 함께 열어 면의 앞뒤와 재질 표시를 추가 확인해야 한다.
